GIGANG 중앙 브라우저 차단 v3.3

[구조]
관리자 대시보드 -> Railway /policy -> 각 사용자 Agent -> Chrome 확장프로그램 -> 실제 사이트 차단

[최초 1회: Railway 서버]
source/railway_server/app.py 수정본을 현재 Railway 수집 서버에 배포해야 합니다.
배포 후 브라우저에서 아래 주소가 JSON을 반환하면 준비 완료입니다.
https://bountiful-nature-production-22ec.up.railway.app/policy
정상 예: {"blocked_domains":[],"updated_at":null}

[관리자 PC]
1. start-all.bat 실행
2. Chrome에서 browser_extension을 압축해제 확장프로그램으로 로드/새로고침
3. 대시보드에서 도메인의 '차단' 클릭
4. Railway 중앙 정책에 저장됨

[사용자 PC]
1. GIGANG Agent 3.3 실행
2. browser_extension 설치
3. 이후 별도 조작 필요 없음
4. Agent가 약 5초마다 Railway 중앙 정책을 받고, 확장프로그램이 정책을 적용함

[확인]
사용자 PC에서 http://127.0.0.1:8765/blocklist 를 열면 현재 적용된 중앙 차단 목록을 볼 수 있습니다.
http://127.0.0.1:8765/health 에서는 central_policy_ok 값도 확인할 수 있습니다.

[차단 해제]
관리자 대시보드에서 '승인' 클릭 -> Railway 목록에서 제거 -> 사용자 Agent에 자동 전파 -> Chrome 접속 복구

[주의]
- 다른 팀원 PC의 Agent를 끌 필요는 없습니다. 127.0.0.1:8765는 각 PC 자기 자신입니다.
- Railway /policy 서버 수정본이 배포되지 않으면 대시보드에서 404 안내가 뜹니다.
- 현재 방식은 Chrome 확장프로그램이 설치된 Chrome에 적용됩니다. Windows 전체 방화벽 차단 방식은 아닙니다.
